# MeeCast: управление с iPhone и передача видео

Название ранее использованной программы установлено по настоящим ресурсам `wnd_meecastqr.xml`, `wnd_full_screen_meecast.xml`, строке `http://www.meecast.com` и зарегистрированным CK610-обработчикам. Сервис уже находится в исходной прошивке. Его код сохраняется; добавлены доступ из нового меню и оформление окна. Исполнение на приставке и актуальное приложение для iPhone пока не проверены.

## Что добавлено в проект

Главное меню сохраняет шесть плиток. Кнопка **0** вызывает `wnd_meecastqr` через существующий GUI create `0x9024DF6C`. Это тот же ресурс/вызов, который использует оригинальный диспетчер при выборе MeeCast QR (`0x900559B0` → `0x900559D8`). Седьмая плитка не добавляется. Новый callback вырос с 316 до 336 байт и остаётся внутри диапазона исходной функции.

Экран MeeCast получил плоский тёмный фон, крупный заголовок, инструкции и поле реального имени приставки. Имена/классы всех виджетов, сигналы и исходные состояния скрытых элементов сохранены. Имя и строки Android/iOS по-прежнему заполняет штатный create-handler; фиктивный QR-код не рисуется. Переводы добавлены в English/Russian/Ukrainian.xml. Изображения и шрифты не добавлялись. Вместе с главным меню и YouTube получается 24 изменённых/добавленных ресурса, 438 файлов, ROOT `0xC0000`; CRC и каждый файл проверяются после повторного чтения cramfs.

## Подтверждение исполняемым кодом

`tools/meecast.py` принимает только оригинальный eCos с SHA256 `64c58484ffaa86996a367c060fcaa46c841f3bcca6d4368b02c17c8b39bf22dc`. Он проверяет инструкции LRW/JSRI/BSR, таблицы и регистрации, а не принимает адрес строки за функцию. Результат — `build/meecast/findings.json`; GNU-листинги — `build/meecast/disassembly/`. Литералы после переходов/возвратов в этих листингах являются данными.

| Путь | Адрес и подтверждённый эффект |
|---|---|
| Запуск сетевых задач | Вызов `0x90014510` по `0x90050E26`; создаются `net_play_task` (`0x90013ED0`) и `net_play_task1` (`0x90013324`) |
| Сервис приложений | Вызов `0x900145D4` по `0x90054130`; создаётся `apps_service` (`0x9001456C`) |
| Приём команд | Таблица девяти записей `0x904ADC98`: key, play, play1, text, scan, conn, info, iptv, apikey |
| Клавиши | Парсер `0x900134FC` → таблица 146 записей `0x904ADD38` → `0x90265AA8`, вставка в системную очередь ввода |
| Переданное видео | play/play1 (`0x900136B0`) → подготовка списка (`0x900135CC`) → `0x9000B078`, создание `wnd_full_screen_meecast` |
| YouTube API key | apikey (`0x90013438`) → ограниченное копирование `0x90010590` → запись `0x900106F8` в `/home/gx/meecast_youtube_apikey.xml` |

Сетевые циклы ожидают готовности сети. Из socket/bind/recv и байтов sockaddr установлены UDP-пары: приём **18920**, ответ **18921**; второй приём **18940**, ответ **18941**. Фактические пакеты конкретного iPhone ещё не захватывались.

| ID клавиши MeeCast | Событие прошивки |
|---|---|
| `0x05` | 0 (`0x30`), новый вход в MeeCast |
| `0x10` | OK (`0x0D`) |
| `0x11` / `0x12` | вверх / вниз (`0x111` / `0x112`) |
| `0x13` / `0x14` | вправо / влево (`0x114` / `0x113`) |
| `0x15` | назад/меню (`0x6D`), обрабатывается штатными оконными путями |

Последние четыре строки таблицы пропускают ID `0x8E`: таблица ищется по ID, прямое обращение как к последовательному массиву было бы ошибкой. Проверяющий код учитывает это.

## Что проверяют тесты

Исполняются оригинальные CK610-инструкции парсера ключа, big-endian декодера и поиска по таблице для payload длиной 1, 2 и 4 байта. Затем моделируется передача события новому callback. Проверены стрелки и кнопка 0; OK на плитке YouTube проходит также оригинальный инициализатор/диспетчер и достигает штатного `0x90012F1C`.

Это офлайн-фикстуры **полезной нагрузки**, не готовые сетевые пакеты. UDP-цикл, асинхронная очередь GUI и конечные платформенные функции заменены заглушками. Тест не доказывает доставку пакетов, фокус окна, фактический запуск приложения или воспроизведение. Поле длины key находится по +12, значение по +16; роль остальных заголовочных байтов полностью не установлена. Поэтому отдельный сетевой клиент с угаданными пакетами не выпускается.

## iPhone и YouTube

На имеющейся заводской прошивке можно проверить встроенную возможность без установки модификации:

1. Найти приложение MeeCast, совместимое с приставкой, в App Store. Наличие именно нужной версии в украинском магазине ещё не подтверждено.
2. Подключить iPhone к той же домашней сети, что и приставка; на iPhone разрешить приложению доступ к «Локальной сети». Подключение приставки кабелем тоже допустимо, если это одна LAN.
3. Открыть штатный пункт MeeCast QR, найти приставку по её имени в приложении и проверить пульт: стрелки, OK, возврат. На модифицированном интерфейсе подготовлен вход кнопкой 0; он ещё не установлен на устройство.
4. Проверить передачу обычного поддерживаемого видео, затем отдельного YouTube-ролика. Успех пульта подтверждает только управление; успех обычного потока ещё не доказывает YouTube.

Строка исходной прошивки «Support IOS 9.0+» — историческая подсказка встроенного интерфейса. Она не подтверждает нынешнюю доступность клиента или его минимальную iOS.

Управление пультом, открытие встроенного YouTube и передача видеопотока — отдельные пути. MeeCast принимает подготовленную ссылку/список потоков; для современного YouTube ещё нужно подтвердить, что iPhone-приложение получает подходящий URL и что штатный плеер понимает его формат, HTTPS и срок действия. Наличие команды apikey не решает декодирование или подпись потока. Значения ключей не публикуются и не изменяются.

Признаков, достаточных для подтверждения стандартного Google Cast/DIAL/UPnP-приёмника, не получено. Отсутствие характерных строк само по себе не доказывает отсутствие произвольного протокольного кода. Обещать появление приставки под обычной кнопкой трансляции в официальном YouTube сейчас нельзя.

Следующий необходимый результат — проверка MeeCast на заводской прошивке и захват обмена iPhone↔приставка для scan/key/play с редакцией ссылок, токенов и персональных данных перед публикацией. Затем можно проверить фактические URL/форматы и писать подтверждённый совместимый клиент при необходимости. Полный изменённый BIN остаётся заблокирован отсутствием восстановления устройства и проверок GUI/метаданных контейнера.
