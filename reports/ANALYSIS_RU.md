## Архитектура и регистрация

База сопоставления файла с памятью — `0x90000000`, C-SKY CK610, little-endian, ABI v1. Путь исходника `ck610m/gx3201/v3_0/src/gxchip_misc.c` согласуется с инструкциями CK610. Голые строковые смещения не используются как адреса кода.

| Callback | Адрес кода | Начало последовательности регистрации |
|---|---|---|
| `win_t2_main_menu_create` | `0x90025BE4` | `0x90072D2A` |
| `win_t2_main_menu_destroy` | `0x90025E14` | `0x90072D3E` |
| `win_t2_main_menu_keypress` | `0x90025ED8` | `0x90072D52` |
| `list_t2_main_menu_keypress` | `0x900261A8` | `0x90072D16` |
| `list_t2_main_menu_getdata` | `0x900265C0` | `0x90072B5A` |
| `list_t2_main_menu_change` | `0x90026760` | `0x90072B46` |
| `app_iptv_create` | `0x9000705C` | `0x90071B6C` |
| `app_netvideo_create` | `0x90015690` | `0x90071634` |

В последовательности регистрации имя загружается в r12, адрес callback — в r13, затем передаются r2/r3 и вызывается `0x9024EC58`. Тело callback декодируется отдельно. `app_iptv_create` и `app_netvideo_create` — обработчики создания окна, их нельзя автоматически считать полноценными функциями старта приложения.

Листинги содержат literal pools: objdump может печатать их как команды. Исполняемые блоки определяются потоком управления; строки после возврата/прыжка через пул сами по себе не доказывают исполняемость.

## Настоящий диспетчер приложений

Из `list_t2_main_menu_keypress` исходный переход категории USB приводит к `0x900557A8`. Функция получает key в r2, читает `select` у `win_t2_main_menu_list`, учитывает вложенные группы и сравнивает выбранное имя. Таблица переходов находится по `0x904B0950`.

| Приложение | Индекс case | Блок case | Фактические вызовы |
|---|---|---|---|
| YouTube | 15 | `0x900559DC` | Чтение настройки через `0x90381B4C`; затем `0x90010A1C` либо `0x90012F1C` |
| IPTV | 18 | `0x900559F4` | `0x900077E4` устанавливает состояние; `0x90008118` выполняет подготовку и следующий вызов |
| MEGOGO | 21 | `0x900559FA` | `0x900118A0`: выделение/инициализация состояния, таблица callback, вызов общего механизма сетевого видео |
| Медиаплеер | 1 | `0x900559B4` | `0x90024DD8`: проверка носителя, открытие `wnd_pvr_media_list` либо сообщение |

При `0x90651642=1` массив имён `0x90651600`, инициализируемый функцией `0x9005577C`, содержит Weather/YouTube/IPTV/Megogo. Поэтому новый callback использует индексы 1/3/2 для плиток YouTube/MEGOGO/IPTV и вызывает исходный диспетчер с key=13. Это сохраняет штатный выбор клиента YouTube и подготовку IPTV.

В тестах исполняются эти исходные инструкции, включая сравнение имён и переход по таблице. Внешние GUI/config-функции и окончательные entrypoints заглушены; сеть, декодирование видео и аппаратное исполнение не проверялись.

## Контейнер

Таблица имеет magic `AA BC DE FA` по смещению `0x20000`, count=8 по `0x20004`. Записи с `0x20005`, шаг 24: имя 8 байт, capacity/used/start как три big-endian u32, ещё 4 байта флагов. Значение флагов до конца не интерпретировано.

| Раздел | Начало | Вместимость | Использовано |
|---|---|---|---|
| BOOT | `0x000000` | `0x020000` | `0x01BD40` |
| TABLE | `0x020000` | `0x000200` | `0x000200` |
| LOGO | `0x020200` | `0x00EE00` | `0x00DADB` |
| V_OEM | `0x02F000` | `0x001000` | `0x0001E7` |
| KERNEL | `0x030000` | `0x290000` | `0x280C00` |
| ROOT | `0x2C0000` | `0x0C0000` | `0x0BC000` |
| DATA | `0x380000` | `0x070000` | `0x000001` |
| AD | `0x3F0000` | `0x010000` | `0x000000` |

Шесть big-endian CRC-слотов начинаются с `0x2019D`, шаг 4. TABLE-слот нулевой; исходная проверка payload пропускает индекс TABLE. У самой таблицы есть отдельная CRC заголовка по `0x201FC`, описанная ниже. Остальные пять слотов точно совпадают с zlib CRC32 **used** байтов соответствующего раздела:

| Раздел | Поле CRC | Значение |
|---|---|---|
| BOOT | `0x2019D` | `BE3399DF` |
| LOGO | `0x201A5` | `A7FC5363` |
| V_OEM | `0x201A9` | `1F586C26` |
| KERNEL | `0x201AD` | `01448568` |
| ROOT | `0x201B1` | `C4981CDD` |

По `0x201FC` хранится big-endian CRC32 `B51B6607` от первых 508 байт таблицы (`0x20000..0x201FB`). Это подтверждено разбором USB-валидатора `0x9002E940` и исполнением исходного блока сравнения вместе с CRC-функцией `0x900CCBCC`. Парсеры проверяют сумму, а пересборка оригинала обновляет её после CRC разделов. CRC, метаданные загрузчика и реальный цикл USB-восстановления разобраны в [UPGRADE_RECOVERY_RU.md](UPGRADE_RECOVERY_RU.md).

ROOT — cramfs little-endian, flags=3, размер `0xBC000`, внутренняя CRC `FCC3EDC4` по смещению +32. При вычислении это поле обнуляется. Найдены 435 обычных файлов, 42 каталога плюс корень, без ошибок декомпрессии. Пакет главного меню добавляет один файл фона и заменяет 15 существующих файлов; обновление YouTube дополнительно добавляет две BMP и меняет два оконных XML, совместно обновляя реестр изображений. MeeCast заменяет собственное окно и три файла переводов. Совмещённый пакет содержит 24 изменённых/добавленных ресурса, всего 438 файлов и занимает `0xC0000`.

KERNEL — ROMFS: superblock size `0x280950`, LZMA по +`0x80`, длина `0x2808C1`. Размер раздела в таблице округлён до 1024 байт. Сумма big-endian u32 первых 512 байт ROMFS равна нулю; сумма заголовка/name inode `0x60..0x80` тоже нулевая. LZMA header `5D 00 00 80 00 FF FF FF FF FF FF FF FF` (8 MiB dictionary, unknown size). Перекомпрессия preset 6, повторная запись размеров/сумм и padding дают точное совпадение оригинального KERNEL.

## Перепаковка и ограничения

Сохранение исходного расположения ROOT вместе с пересобранным KERNEL и пересериализованными известными полями таблицы даёт точный исходный полный BIN. Это проверка восстановления **оригинала**, а не готовности изменённой прошивки.

Принудительная перепаковка исходного ROOT семантически идентична, но меняет размещение и дедупликацию блоков; отличаются 507 025 байт, fsid.blocks и CRC. Все 435 файлов и их mode/UID/GID совпадают. Это допустимое различие файловой системы, но принятие его загрузчиком ещё не проверено.

Новый callback занимает только первые 336 байт диапазона исходного list-handler `0x900261A8..0x900265C0`, не требует выдуманного code cave или добавления кода поверх BSS. Он сохранён отдельно; исходный eCos не изменялся. Кнопка 0 загружает исходное имя окна MeeCast `0x904BCFF4` и вызывает штатный GUI create, как блок оригинального диспетчера `0x900559B0`. Оставшиеся ссылки на старые case-блоки, жизненный цикл GUI и восстановление исходного состояния требуют проверки до интеграции. Все смещения и байты записаны в `build/patch_manifest.json`.

USB-дамп реального устройства подтвердил точное совпадение диапазона до DATA с оригиналом. Добавлен отдельный 224-байтный create-finalizer внутри того же диапазона list-handler, по `0x900262F8`: он вызывается BSR из `0x90025D48` вместо исходного `movi r2,0`. Подробности проверки дампа и исправления фокуса — в [USB_DUMP_RU.md](USB_DUMP_RU.md). Суммарный размер key-callback и finalizer — 560 байт из 1048; остальные функции/литералы за пределами этого диапазона не используются для размещения кода. Полный модифицированный BIN не создавался.
