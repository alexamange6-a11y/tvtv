# Проверка USB-дампа с устройства пользователя

Проверен загруженный `dump_all.bin`. Размер **4 128 768 байт (`0x3F0000`)**, SHA256 `2cab1ab209adb7762d3fd9dd950762f211f86e2aeb9244927f74ce338b88d69e`. Исходный файл не изменялся. Локальная копия находится в исключённом из Git каталоге `private_backups`, с правами только на чтение. Содержимое DATA не публикуется и не включается в пакет проекта.

## Подтверждено сравнением байтов

Диапазон **`0x000000..0x37FFFF`** полностью совпадает с заводским BIN проекта. В него входят BOOT, TABLE, LOGO, V_OEM, KERNEL, ROOT, промежутки и заполнение разделов. Это подтверждает соответствие используемых исходников/ресурсов реальной прошивке приставки и preimage подготовленных патчей.

| Проверка | Результат |
|---|---|
| Таблица разделов по `0x20000` | Все восемь записей совпадают с оригиналом |
| Внешние CRC32 | Все пять заполненных контрольных сумм верны |
| CRC-слот раздела TABLE | Нулевой; исходный цикл payload-проверок пропускает TABLE |
| Независимая CRC заголовка таблицы | `B51B6607` по `0x201FC`; сумма первых 508 байт верна |
| ROMFS | Размер, сумма superblock и сумма inode верны |
| eCos после LZMA-декомпрессии | Побайтно совпадает; SHA256 `64c58484ffaa86996a367c060fcaa46c841f3bcca6d4368b02c17c8b39bf22dc` |
| ROOT/cramfs | CRC верна; 435 файлов, содержимое совпадает с оригиналом |
| DATA (`0x380000..0x3EFFFF`) | Присутствует целиком; 219 006 байт отличаются от заводского заполнения |
| AD (`0x3F0000..0x3FFFFF`) | В USB-экспорте отсутствует; ёмкость по таблице 65 536 байт, used=0 |

DATA следует сохранять целиком: поле used в таблице равно 1, но фактическое содержимое за этим байтом не пустое. Нельзя переносить только один байт DATA или заменять весь раздел заводским заполнением. Назначение всех записей DATA и наличие уникальных ключей по содержимому пока не разбирались.

В заводском файле отсутствующий хвост AD заполнен FF. Это не даёт основания считать таким же хвост **реального устройства**: его байты не прочитаны. Анализатор не дописывает FF и не создаёт фиктивный «полный SPI-дамп». USB-копия сама по себе не подтверждает возможность восстановления приставки, которая перестала загружаться.

Дополнительно прослежен штатный цикл восстановления загрузчика: он пишет `0x20000..0x3EFFFF`, сохраняя BOOT и AD. Дамп содержит все байты этого диапазона, включая DATA. Это уточняет его потенциальную пригодность для данного пути, однако проверки входного файла и физическое восстановление не подтверждены. Готовый recovery-файл не создаётся. Подробности и границы проверки — в [UPGRADE_RECOVERY_RU.md](UPGRADE_RECOVERY_RU.md).

## Повторная проверка

```bat
.venv\Scripts\python.exe tools\dump_analysis.py dump_all.bin --output build\backup_analysis.json
```

До этого нужно выполнить обычную подготовку проекта через `build.bat`. Анализатор принимает только известную структуру таблицы и размеры `0x3F0000` или `0x400000`, проверяет CRC и файловые системы. Обычный строгий парсер заводского полного BIN не ослаблен. Отчёт содержит только структуру, размеры, хеши и число отличий; строки конфигурации, ID и ключи не извлекаются.

Тесты проверяют экспорт без AD, обнаружение изменений DATA за пределами used=1, запрет неожиданных усечений/повреждений и отсутствие вывода тестовых конфиденциальных данных. Даже образ полного размера не получает отметку о проверенном физическом восстановлении.

Сборка умеет дополнительно проверить локальный дамп конкретного устройства:

```bat
.venv\Scripts\python.exe tools\build.py --device-dump dump_all.bin
```

Она требует точного совпадения загрузчика, кода и ресурсов с поддерживаемыми preimage. Даже корректные CRC не разрешают сборку патчей для другого кода. Сам дамп, DATA и локальный `build/device_backup_analysis.json` не включаются в исследовательский ZIP. Полный модифицированный BIN по-прежнему не выпускается.

## Дальнейшая доработка меню

Подтверждён конфликт исходного `win_t2_main_menu_create`: он заполняет старые категории и в зависимости от `0x9064A73C` ставит фокус либо на OK-кнопку, либо на список. Для новой горизонтальной навигации подготовлен finalizer размером **224 байта**, размещённый сразу после 336-байтного нового key-callback, внутри старого диапазона list-handler. По `0x90025D48` исходная инструкция `movi r2,0` заменяется двухбайтным BSR в этот finalizer. Патч хранится отдельно; eCos и полный BIN с ним не создаются.

Finalizer сбрасывает старые флаги вложенных категорий и выбор списка, ограничивает номер плитки диапазоном 0..5, скрывает старую седьмую плитку/подсказку активации, фокусирует настоящий список и перерисовывает шесть иконок. Список получил ненулевую область 1×1 в нижнем углу вместо 0×0. Исходные действия create до эпилога остаются на месте.

В тестах выполняются BSR, исходный эпилог возврата и все инструкции finalizer; проверяются стек, сохранённые регистры, флаги, фокус и ровно одна выделенная плитка. GUI-функции заменены заглушками. Полный исходный create и асинхронный жизненный цикл приложений не эмулируются. Поэтому аппаратная проверка остаётся обязательной, несмотря на успешные тесты.
